# Hao Fitness Log

## 日历、逐组成绩与三语界面

顶部语言菜单支持中文、日本語、English，选择会保存在当前浏览器。界面文案通过离线词典切换，用户自定义动作名和历史名称保留原文。切换语言时保留正在填写的输入内容。上次训练成绩按每组独立显示重量、次数和 RIR，便于逐行比较。

「カレンダー」显示完成记录以及当前分割的下一次训练安排。完成训练后，下一训练日按计划顺序生成，读取最近相关部位的训练时间与设置间隔。填写训练后反馈后会更新安排。疲劳 3 分增加 24 小时排期余量，4–5 分增加 48 小时，强烈疲劳下标为暂定并提示检查状态。这些小时数是本地保守排期规则，实际恢复需用户确认。缺少反馈时不假设疲劳评分。用户可改期、暂不采用或恢复自动安排。

应用使用本地规则运算，未接入云端 AI 服务。日历维护当前计划的下一次安排，完成下一次训练后重新计算后续安排。手动日期通过原训练记录的稳定 ID 关联，删除来源记录后对应自动安排消失。

新增 `js/calendar.js`、`js/i18n.js`、`calendar.css`、`tests/calendar.test.cjs`、`tests/i18n.test.cjs`。数据版本升级至 4，存储键仍为 `haoFitnessLog:v1`，新增 `calendarOverrides` 保存手动安排；原始训练历史保留。语言偏好独立保存在 `haoFitnessLog:language`。

此次执行 34 项 Node 测试并全部通过。Chrome 隔离环境验证了训练完成→疲劳反馈→日历、手动改期保存、中日英切换及表单保持、逐组独立卡片，以及 390／320 px 下全部六个页面的宽度。实体手机未实测。修改前源文件已另存 ZIP 备份。

用于制定力量训练计划、逐组记录训练和查看重量变化的静态 Web App。界面使用日语，以 HTML、CSS 和原生 JavaScript 实现，图表和图标使用 SVG。

## 本地运行

1. 将整个项目文件夹放在固定位置，保留其中的文件和子目录。
2. 用最新版 Chrome 打开 `index.html`。双击文件即可使用，也可以从浏览器的「打开文件」菜单进入。
3. 选择「トレーニングプラン」开始记录。首次打开时提供 3 分割、4 分割和 5 分割模板，历史为空。

运行无需安装依赖、构建、联网或启动服务器。Node.js 仅用于运行下方的数据逻辑测试。

## 功能

| 页面 | 功能 |
| --- | --- |
| ダッシュボード | 预览今日计划、上次训练、近期进度和下一次训练的候选日期。汇总本地日期所在周的训练次数、总组数和训练量，并显示最近完成的训练。统计范围为周一至周日，训练量为各组「重量 × 回数」之和。 |
| トレーニングプラン | 独立编辑 3 套计划。新增、编辑和删除训练日及动作，选择训练部位，用拖动手柄或上下箭头排序。逐组填写重量、次数和可选 RIR，支持新增、复制和删除组，显示该动作最近一次正式训练的成绩和下次建议。 |
| 履歴 | 按训练日期倒序查看完成记录，展开查看每组数据。支持按起止日期和部位筛选、编辑记录及确认删除。 |
| 進捗 | 按动作查看每次训练的单组最高重量。同日多次训练分别绘制。只有一条记录时显示单点，无记录时显示空状态。 |
| リカバリー | 按部位查看最近训练、经过时间和最新自评。可设置训练日间隔、填写训练前后状态、查看并修改过去的恢复反馈。 |

### 记录一次训练

「今日のプラン」会根据所选分割的卡片顺序推荐下一天。没有可用于轮换的记录时，从第一天开始。当天已完成所选分割中的训练日时，会显示该训练日及完成标记。「前回の記録」显示最近一次训练中首个动作的最后一组，「最近の進捗」显示同一动作各次训练的最高重量趋势。

在对应训练日填写每组的「重量 (kg)」和「回数」。重量可为 0，回数须为正整数。RIR 可留空，填写时须为 0–10 的整数，表示估计还能完成几次。通过「セットを追加」添加空白组，也可以点复制图标沿用该组的数值。

每次输入都会立即保存草稿。点击「トレーニング完了」时，页面会跳过全空组，检查其余各组，并要求至少有一组有效记录。保存成功后，该训练日的草稿会清除，正式记录随即纳入统计和图表。

添加已有同名种目时，会复用已有动作 ID，可跨计划查看它的训练成绩。在某个计划中编辑动作名只改变该训练日显示的名称。每条正式历史保存训练日、部位、动作名和各组成绩的快照，调整、删除计划卡片或动作时仍可查看历史。

### A2 训练建议

在动作卡片展开「次回のトレーニング提案」，可查看建议、判断理由以及实际参考记录。用「目標を編集」设置该动作的次数范围、RIR 范围和最小增重档位。尚未设置的动作采用 8–12 回、RIR 1–3、2.5 kg 档位。通过「今回は見送る」暂时隐藏本次建议，也可以再次展开。

系统按训练日期和完成时间读取最近记录，取每次最重重量对应的工作组。低于该重量的组不参与比较。如果最近两次的最重重量不一致，或者对应组缺少 RIR，会显示「データ不足」。回数比较使用真实的中位数组，偶数组数取较低的一组。

- 最近两次所有对应组均达到目标次数上限，且每组 RIR 为正、不低于目标下限时，才考虑增加一个最小档位。默认档位增幅上限为当前重量的 5%。自重动作保持 0 kg。
- 表现稳定或上升、RIR 在目标范围内且未达次数上限时，可建议同重量加 1 次。连续两次下降各至少 2 回，或连续两次出现接近力竭或高主观疲劳信号时，才会提示考虑减负。一次异常只会抑制加量。
- 只有用户点「下書きに反映」时，才会把可用的重量和次数填到一个空训练组。动作中已有填写内容时会禁用该按钮，RIR 留给实际训练时记录。

### A3 恢复与训练日程

完成训练后的状态表单可以跳过。训练前可从 Dashboard 或「リカバリー」页面填写「コンディションチェック」。疲劳、各部位酸痛、睡眠时长、睡眠质量和主观感受均为选填。之前的反馈可以在恢复历史中修改，编辑保留实际填写时刻。

- 「次回の候補日」以最近一次包含目标部位的训练为起点，包含其他分割中的记录。将记录的本地训练日期和完成时刻作为基准，再加上训练日设定的间隔。默认 48 小时，可选择 72 小时或输入自定义小时数。候选日期是当前设置下最早可考虑的日期，可能已经过去，需结合状态判断。无相关训练记录时不生成候选日期。
- 达到间隔且反馈充分、无明显问题时显示「トレーニング候補日です」。系统查看最新一份自评，要求其在最近相关训练之后且默认不超过 24 小时，并包含疲劳和所有相关部位的酸痛。未到间隔、反馈缺失或较旧、存在中等疲劳或睡眠信号时显示「コンディションを確認しましょう」。近期自评疲劳或相关部位酸痛达到 4 分，或选择「かなり疲れている」时，显示「休息・調整を検討」，并抑制该动作的增重和加次数建议。
- 最近训练的组数、训练量和 RIR 用作判断参考。候选时间始终来自训练记录和用户设定的间隔，不会根据训练量自动增加休息小时。该模块用于安排日程，无法判定实际恢复程度或超量恢复时间。强烈疼痛或异常症状时，请勿依据候选日继续训练。

## 数据保存与使用限制

- 数据继续使用 `localStorage` 键 `haoFitnessLog:v1`，状态的 `schemaVersion` 为 `4`。版本 1、2、3 的数据在读取时升级到内存，下一次成功保存才写回。同一批训练历史、计划、草稿、名称快照和 ID 会保留。仅打开页面不会写入升级结果。
- 动作目标、建议偏好、恢复偏好和恢复反馈各自存储。建议与候选日期从原始记录实时计算。恢复反馈可以关联过去的训练，即使训练历史之后删除，训练反馈仍可在「リカバリー」查看。旧版页面无法直接读取已写入的版本 3 数据。
- 草稿按训练日 ID 隔离。提交时，新增历史和清除草稿共用一次写入。写入失败时会提示并保留已保存的历史及草稿。发现损坏或不兼容的数据时，应用会提示并保留原值。
- 建议在同一浏览器、同一用户资料中从固定路径打开。浏览器对 `file://` 本地存储的处理可能不同，移动或改名文件、换浏览器或用户资料后，原记录可能不会出现在新位置。清除浏览器站点数据会删除记录，隐私浏览中的记录也可能在关闭后清除。
- 记录仅保存在当前浏览器，应用没有内置备份、导入或云同步。建议一次使用一个标签页。如果应用发现另一标签页修改了数据，会提示先刷新再继续。
- 回滚 Git 备份只含升级前的源文件。浏览器记录保存在原位置，源文件回滚不会回滚浏览器数据。
- 已在 Windows 上的 Chrome 验证直接打开文件和手机尺寸模拟。其他浏览器及实体手机的兼容性尚未实测。
